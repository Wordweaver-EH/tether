# Replay determinism repair

## Result

Simulation math is now `ieee-arithmetic-v1`: rule-state transitions use specified arithmetic and fixed-iteration approximations instead of host `Math.atan2`, `sin`, `cos`, `hypot`, or `sqrt`. Turning compares the normalized aim with the allowed-turn cosine, takes the aim directly if reachable, otherwise applies one bounded rotation. Exact 180-degree ties remain counterclockwise. Square roots use exponent-seeded eight-step Newton iteration, including subnormal scaling. Turn sine/cosine uses a fixed 16-term recurrence on [0, pi]; cached per-turn rotations avoid per-tick transcendental work.

No experiment constants, speeds, turn rate, timing, visibility rules, collision epsilon, or mechanics were changed. The floating-point implementation intentionally changes last-bit trajectories; old behavioral measurements must not be represented as measurements of this build.

JSONL-v1 record structure remains, with an additional metadata field `simulation_math`. Logs without this version are rejected with an explicit instruction to use their original build, rather than silently comparing incompatible trajectories. This is **not backwards-compatible simulation of legacy logs**. Historical browser logs already failed in Node; old logs should be retained with the original source/runtime for analysis. For the committed September smoke log, use the original smoke build (documented commit `6ca879d`) in the producing Edge runtime and its Mind View, where the recorded smoke verification passed. Do not strip the new math tag or regenerate hashes to force acceptance. For any other legacy log, use its recorded `build_id` and the associated archived source/runtime; if that provenance is unavailable, verifiable replay cannot be promised. The metadata format tag alone is insufficient to claim replay compatibility.

Also fixed:
- `src/log.js` no longer imports `node:util`; browser-safe recursive equality checks all JSON fields, independent of key order
- Named experiment overrides are logged and reconstructed, rather than mislabeled as default constants

## Verification

At this work checkpoint the complete concurrent checkout passed 98 tests, including four new determinism regressions:
- arithmetic approximation error checks and edge cases
- a 3,600-tick Mode B log and replay with all five host math functions replaced by throwing stubs
- replay of experiment overrides and explicit incompatible-version rejection
- byte-for-byte equality of 3,600-tick logs generated by normal Node and Node `--jitless`, then 601 samples verified

Existing tests retain the 1e-11 rule-value tolerance and 1e-9 collision epsilon, and the seeded 20,000-step fuzz test in both modes passes. A reproducible 100,000-sample numerical comparison (`node tools/math-audit.mjs`) reports:

| Quantity | Maximum observed error versus host/prior implementation |
| --- | ---: |
| sqrt relative | 2.220446049250313e-16 |
| hypot relative | 4.440892098500626e-16 |
| sin/cos absolute | 7.771561172376096e-16 |
| single-turn facing component absolute | 3.3306690738754696e-16 |

These sampled results establish roundoff-scale numerical changes, not a proof of correct rounding or identical long-run outcomes. Sensitive boundary cases can still select different outcomes than the historical implementation; new evidence must use the new build consistently.

### Reproducible check on a permitted local setup

The following server command was corrected during delivery: the normal game server intentionally does not expose `tools/`. The new diagnostic server is a separately tested, post-evaluation helper; it does not change the frozen simulation or supply missing browser evidence. See [the current reproduction guide](../../REPRODUCE.md).

1. Run `node tools/serve-replay-probe.mjs` from the repo root
2. In a browser allowed to access that server, open `http://localhost:8766/tools/replay-probe.html`
3. Click **Generate browser log**. It simulates 30 seconds of fixed seeded inputs, verifies in the browser, shows its hash and user agent, and downloads `tether-browser-replay.jsonl`
4. Run `node tools/verify-browser-replay.mjs /path/to/tether-browser-replay.jsonl`
5. Require 3,600 ticks, 601 verified samples, and exact final-hash agreement with the browser. Save browser/runtime versions and the generated fixture with the result
6. Repeat in the target browser/runtime pair and with a full human-session log; the same verifier supports both

The probe has no dependencies and does not upload logs. A browser-generated fixture must never be replaced by a Node-generated file mislabeled as browser evidence.
